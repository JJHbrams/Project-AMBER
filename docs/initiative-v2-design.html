자율발화(Initiative) v2 — 동작 설계

ProjectIntelContunuum · 기준 커밋 2e85625 (v0.2.1) · overlay/bubble/initiative.py, overlay/main.py, overlay/bubble/bubble_manager.py

이 문서는 "유휴 시 말을 건다"까지만 구현된 현재 상태에, 발화 이후의 결과가 어디에 어떻게 쌓이는가를 붙이는 설계다. 세 장의 그림 — 플로우차트(제어 흐름) · 타이밍 그래프(시간 축 실동작) · 액션 그래프(결과 → 부작용 → 학습 루프) — 로 나눠 그렸다.

구현됨 (v0.2.1) 게이트 / 조건 사용자에게 보이는 것 신설 (v2 제안) 현재 결함

1. 플로우차트 — 5단계 라이프사이클

한 번의 _tick()이 통과해야 하는 게이트부터, 발화 후 결과 판정과 피드백 버스까지.

2. 타이밍 그래프 — 시간 축 실동작

기본 설정값(idle_min 600s · min_gap 1800s · dwell 25s · backoff_max 4) 그대로일 때 4시간 창에서 실제로 몇 번, 언제 말하는가.

2-b. 발화 한 건의 확대 타이밍 (초 단위)

3. 액션 그래프 — 결과 → 부작용 → 학습 루프

"자율발화하고 그 뒤는 모르겠고"를 끊는 부분. 결과 3종이 각각 어느 저장소에 무엇을 남기고, 그게 어떻게 설정으로 되돌아오는가.

4. 현재 구현에서 발견된 결함

위 그림의 붉은 지점. 전부 실제 코드 확인 결과이며, v2 설계는 이걸 고치는 것을 전제로 한다.

F1
ignored 가 신호되지 않는다. bubble_manager._on_speech_faded() 는 _clear_nudge_state() 로 색·클릭 오버라이드만 정리하고 엔진에 아무것도 알리지 않는다. 대신 _speak() 가 발화 시점에 ignore_streak += 1 로 낙관적 선증가한다. → 결과가 관측된 적이 없다.
F2
모든 사용자 입력이 백오프를 리셋한다. main.py:1078 의 _on_bubble_submit() 이 무조건 notify_engaged() 를 부른다. nudge 와 무관한 평범한 대화도 streak 을 0 으로 만든다 → 활발히 쓰는 사용자에게는 무시 백오프가 사실상 작동하지 않는다.
F3
폐기된 발화도 비용을 전액 지불한다. _finish_phrasing() 에서 화면이 더 이상 clear 하지 않으면 렌더를 건너뛰는데, last_spoke·source.last_fired·ignore_streak 은 이미 _speak() 에서 소비됐다. 보이지도 않은 발화가 "무시"로 집계된다.
F4
메타가 소실된다. Nudge.source_key 와 topic, curiosity id 는 _speak() 이후 어디에도 안 남는다. 생존하는 건 _pending_engage 문자열 하나뿐 → 결과 판정 시점에 "어느 소스였나"를 알 수 없어 후처리 자체가 불가능하다.
F5
대화 연속성이 끊긴다. 클릭 시 engage_prompt 만 세션에 전송되고, 방금 화면에 떠 있던 nudge 문구(프레이징된 실제 대사)는 세션이 모른다. 사용자 눈엔 "캐릭터가 A 라고 말 걸어서 답했는데 A 를 기억 못 함"으로 보인다.
F6
취소 경로가 없다. 풍선을 클릭하면 engage_prompt 가 있으면 즉시 전송, 없으면 입력창이 열린다. "클릭했지만 답은 안 함"이라는 중간 상태가 관측되지 않는다.

집계를 미뤄도 되는가 — 무엇이 lossy한지

결정(집계 시점·보관 위치)은 미뤄도 된다. 근거는 셋:

  • activity_log.created_at 이 datetime('now','localtime') — 초 단위라 시간대별 집계가 가능하다.
  • 이 테이블에는 purge/retention 로직이 없다. curiosities 는 purge_processed_curiosities 로 정리되지만 activity_log 는 삭제 코드가 아예 없어 쌓인 게 사라지지 않는다.
  • 후보 두 안(재쿼리 / 요약 테이블) 모두 같은 원장에서 백필된다 — 나중에 정해도 과거 데이터를 그대로 쓴다.

하지만 "무엇을 적재할지"는 미루면 안 된다. 안 남긴 값은 소급 복원이 불가능하기 때문. 그래서 두 가지를 결정과 분리해 먼저 확정했다:

항목없으면 생기는 일
latency같은 ignored 인데 3초 만에 "나중에"(봤고 관심 없음 — 강한 부정)와 25초 dwell 을 다 채우고 페이드(자리에 없었을 가능성 — 신호 아님)가 한 줄로 뭉개진다. 백오프를 둘에 똑같이 먹이는 건 틀렸고, 과거 로그에서는 되살릴 수 없다. engaged 도 즉답과 장고가 안 갈린다.
detail 형식topic 은 자유 텍스트라 구분자·key= 가 섞일 수 있다. 첫 " | " 앞을 기계 판독 구간(값에 공백 없는 source/outcome/latency 만)으로 고정하고 자유 텍스트를 뒤로 뺐다 — topic 에 outcome=fake | source=evil 을 넣어도 파서가 안 깨지는 것으로 확인. 뒤에 필드를 더해도 기존 파서는 그대로 동작한다.

결과 판정 창 ≠ 답할 수 있는 창

초기 구현은 dwell(25초) 안에서만 답장이 가능했다. 그게 틀렸다 — 데스크톱 상주 캐릭터의 기본 사용법은 아무 때나 캐릭터를 눌러 "마지막에 뭐라고 했더라"를 확인하고, 자율발화였으면 그때 답하는 것이다. dwell 은 결과를 관측하는 창일 뿐이다.

  • 복원된 풍선이 자율발화면(_last_was_nudge) 답장 아이콘과 문구 prepend가 살아난다. 마지막이 평범한 응답이면 아이콘 없이 그냥 새 대화를 시작한다.
  • 아이콘 표시 조건을 "판정 대기 중"에서 "답장 콜백이 살아있는지"(_nudge_reply_cb)로 바꿨다. 이 콜백은 새 발화나 새 대화 턴이 올 때만 해제된다.
  • 뒤늦은 답장은 late_engaged 로 별도 기록 — 이미 남긴 ignored 를 소급 수정하지 않아 "발화 1건 = 결과 1건"이 유지된다. 백오프는 리셋되고 curiosity 해소도 이 경로에서 걸린다.
  • 답장까지 간 발화(engaged)는 되살릴 대상이 없으므로 슬롯을 비운다.

구현하며 추가로 드러난 것

설계 단계에선 안 보였다가 배선하면서 나온 두 가지 — 둘 다 결과가 잘못 귀속되는 문제라 같이 고쳤다.

  • 발화 교체 경로 — 결과 미확정 상태에서 새 발화가 화면을 덮으면 이전 발화는 영영 판정될 기회가 없다. show_nudge() 진입 시 직전 발화를 먼저 무시로 마감한다.
  • 입력창 닫힘 콜백의 순서 함정 — 이미 열려 있던 입력창을 닫으면 그 on_close 가 발화하는데, _nudge_awaiting_reply 를 먼저 세워두면 방금 뜬 발화가 무응답으로 마감된다. 반드시 hide() 를 모두 끝낸 뒤 플래그를 세운다.
