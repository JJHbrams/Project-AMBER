# 시스템 매뉴얼

> 이 폴더의 Markdown은 사람이 읽는 원문이다. Obsidian과 대시보드는 같은 페이지를 읽지만, 실행 중인 대화·저장 데이터·설정값을 이 문서에 기록하지 않는다.

## 이 매뉴얼이 답하는 질문

- **무엇을 하려는가?** 먼저 [[getting-started|시작하기]]에서 사용 시나리오를 고른다.
- **어떻게 연결되는가?** [[architecture|아키텍처]]에서 화면, 정책, 저장소, Wiki의 경계를 확인한다.
- **어디에 남겨야 하는가?** 일시적 맥락은 [[session-memory|세션과 메모리]], 재사용할 지식은 [[wiki-kg|Wiki와 지식 그래프]]를 따른다.
- **무엇이 기대와 다른가?** [[self-diagnosis|자가진단]]의 관찰→근거→복구→실행 검증 순서를 사용한다.

## 읽는 순서

```mermaid
flowchart LR
  A[목표 또는 이상 징후] --> B{새 기능인가?}
  B -- 예 --> C[시작하기와 관련 기능 페이지]
  B -- 아니오 --> D[자가진단과 관련 기능 페이지]
  C --> E[작은 범위에서 실행]
  D --> F[읽기 전용 근거 수집]
  E --> G[원래 실행 환경에서 확인]
  F --> H[복구 후 원래 경로 재실행]
```

텍스트 대체 설명: 새 기능은 시작 가이드와 해당 기능 문서를 읽고 작은 범위에서 실행한다. 이상 동작은 자가진단에서 관련 페이지와 기대 동작을 먼저 확인한 뒤, 읽기 전용 근거를 모아 복구하고 원래 실행 경로를 다시 확인한다.

## 페이지를 읽는 공통 틀

각 기능 페이지는 가능한 한 다음 순서를 가진다.

1. **목적과 사용 시점** — 어떤 문제를 해결하는지와 적용 범위.
2. **정신 모델** — 데이터와 책임이 어디에 있는지.
3. **절차와 예시** — 중립적 자리표시자(`<data-root>`, `<scope>`, `<page-id>`)를 쓴 재현 가능한 흐름.
4. **기대 동작과 자가 점검** — 성공 기준, 증상, 확인할 근거, 복구 방법.
5. **안전과 한계** — 자동으로 보장되지 않는 일과 변경 전 확인할 사항.

## 기대 동작

- Obsidian과 대시보드는 같은 관리형 Markdown 원문을 표시한다.
- 제목·별칭·분류·본문 검색으로 관련 기능 페이지를 찾을 수 있다.
- 내부 Wiki 링크는 존재하는 페이지로 이동하고, 각 페이지에서 기대 동작과 복구 절차를 찾을 수 있다.
- 제품 업데이트 후에는 설치된 매뉴얼 버전과 패키지 manifest의 버전이 일치한다.

## 증상, 확인, 복구

| 관찰된 증상 | 먼저 확인할 근거 | 복구와 재검증 |
| --- | --- | --- |
| 매뉴얼 폴더가 비어 있다 | 활성 `<data-root>`, installer 출력, `.install-manifest.json` 존재 여부 | 의도한 데이터 루트에 installer를 실행하고 11개 관리 페이지를 다시 센다 |
| 대시보드와 Obsidian의 내용이 다르다 | 두 화면이 같은 vault 원문을 읽는지, 파일 수정 시각과 `manual_version` | 경로를 맞추고 화면을 새로 연 뒤 같은 페이지 제목·요약을 비교한다 |
| 링크가 열리지 않거나 검색되지 않는다 | 대상 페이지의 `id`·별칭·frontmatter와 Wiki 링크 | [[wiki-kg]] 절차로 링크를 고치고 동기화·lint·재검색한다 |
| 업데이트 뒤 개인 메모가 사라질 위험이 있다 | 해당 파일이 관리 manifest에 포함되는지 | 개인 내용을 관리 경로 밖의 별도 Wiki 페이지로 옮긴 뒤 [[installation-update]] 절차를 따른다 |

## 안전과 한계

이 매뉴얼은 현재 설치에서 사용 가능한 권한이나 도구 목록을 자동으로 보장하지 않는다. 예시는 중립적 자리표시자를 사용하며, 실제 경로·이름·비밀값을 공유 문서에 복사하지 않는다. 관리형 페이지를 직접 편집한 내용은 재설치 때 교체될 수 있으므로 장기 기록은 별도 Wiki 페이지에 둔다.

## 문서 기여와 버전

매뉴얼 페이지의 `id`와 파일 이름은 ASCII 식별자를 사용한다. 본문에서는 `[ [<page-id>] ]` 또는 `[ [<page-id>|표시 이름] ]` 형식의 Wiki 링크를 사용한다(공백은 이 설명을 실제 링크로 해석하지 않게 하기 위한 것이다). 설치 프로그램이 관리하는 매뉴얼 페이지는 제품 버전에 맞춰 갱신될 수 있으므로, 개인 노트·실험·프로젝트 기록은 이 관리 경로 밖의 Wiki 페이지에 둔다. 링크나 frontmatter를 고친 뒤에는 [[wiki-kg|동기화와 lint]]를 수행한다.
