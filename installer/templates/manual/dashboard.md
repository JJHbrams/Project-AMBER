# 대시보드

> 대시보드는 활성 데이터와 vault 페이지를 편리하게 보여 준다. 별도의 문서 원문이 되면 안 된다.

## 화면 구성

대시보드는 같은 저장소를 서로 다른 관점으로 보여 주는 탭을 제공한다. 표시되는 데이터와 기능은 설치 상태·연결된 서비스에 따라 달라질 수 있으므로, 비어 있는 탭은 곧바로 오류를 뜻하지 않는다.

| 탭 | 용도 | 첫 점검 |
| --- | --- | --- |
| Overview | 서비스·저장소의 요약 상태 | 연결 대기·오류 메시지와 새로고침 |
| KG Graph | Wiki 관계와 그래프 연결 | 노드 수, 링크, 동기화 상태 |
| Wiki Nodes | 페이지 원문과 메타데이터 탐색 | 대상 ID·제목·frontmatter |
| Memories | 보존된 세션 관련 기록 확인 | 범위·시간·검색 조건 |
| Manual | 설치된 매뉴얼 페이지 읽기 | vault 경로와 설치 상태 |
| Directives | 적용 정책과 관리 출처 확인 | source·scope·우선순위 |
| Semantic | 의미 검색·인덱스 상태 | 서비스 연결과 검색 결과 |
| Identity | 저장된 정체성 표현의 요약 | 민감한 값 노출 여부와 변경 범위 |

## 매뉴얼을 페이지처럼 읽는 법

Manual 탭은 vault의 `<db-root>/docs/guides/engram-manual/` 원문을 읽는다. 대시보드는 원문을 복제하지 않는다. 상단 검색은 제목·요약·분류·태그·본문을 대상으로 하고, 사이드바 분류는 같은 페이지 목록을 좁혀 준다. 내부 Wiki 링크는 페이지 링크로 변환되고, 이전/다음 기록·breadcrumb·목차를 통해 문서 사이를 이동한다.

1. Manual 탭을 열고 검색어 대신 기능 이름이나 이상 징후를 입력한다.
2. 결과의 요약을 읽고 가장 가까운 페이지를 연다.
3. breadcrumb로 매뉴얼 첫 페이지 또는 현재 분류로 돌아간다.
4. 목차에서 필요한 섹션으로 이동하고, 관련 페이지 링크를 연다.
5. Mermaid 도식 아래의 `텍스트 대체 설명`도 함께 읽어 도식 없이도 절차를 확인한다.

```mermaid
flowchart LR
  A[검색 또는 분류] --> B[매뉴얼 페이지]
  B --> C[목차와 관련 링크]
  C --> D[기대 동작·점검·복구]
  D --> E[실제 탭 또는 런타임 확인]
```

텍스트 대체 설명: 검색이나 분류로 페이지를 열고, 목차와 관련 링크를 따라 필요한 진단 섹션을 찾은 뒤 해당 기능을 실제 탭이나 런타임에서 확인한다.

## 기대 동작

매뉴얼 페이지 뷰어는 `<db-root>/docs/guides/engram-manual/`의 파일을 표시한다. 탐색은 원시 Wiki 링크 문법 대신 분류와 내부 링크를 제공한다. Mermaid 블록은 다이어그램으로 렌더링되며, 링크로 진입한 Manual 페이지도 대시보드의 Manual 탭을 유지한다.

## 이상 징후

- 매뉴얼 페이지가 비어 있거나 오래된 내용이다.
- 탐색에 페이지 제목은 보이지만 페이지를 열 수 없다.

## 점검

대시보드가 활성 데이터베이스 루트를 사용하는지 확인하고 대응 Markdown 파일이 존재하는지 점검한다. 파일 수정 시간이 바뀐 뒤 페이지를 새로 고친다. 검색 결과가 없으면 제목뿐 아니라 본문·태그·분류를 나누어 검색하고, 링크가 깨지면 해당 페이지의 frontmatter ID와 `[[self-diagnosis|표시 이름]]`처럼 실제 페이지 ID를 가리킨 대상이 일치하는지 확인한다.

## 복구

대시보드 프로세스를 재시작하고 매뉴얼 설치 상태 파일을 확인한다. 관리 페이지가 없으면 installer를 다시 실행한다. 설치 manifest에 없는 사용자 페이지는 보존한다. 그래프·의미 검색만 오래되면 vault 파일을 덮어쓰지 말고 [[wiki-kg]]의 동기화와 lint 절차를 수행한다.

## 제한과 주의

- 대시보드는 제어·관찰 화면이며, 파일 편집기나 백업 시스템을 대체하지 않는다.
- Manual 탭의 문서는 관리형 페이지일 수 있다. 개인 메모는 관리 manifest에 없는 별도 Wiki 페이지에 둔다.
- 캐시 초기화나 프로세스 재시작은 일시적인 표시 문제를 분리하는 방법이지, 데이터 손상의 복구 증거가 아니다.
